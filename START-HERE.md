# START HERE

You normally do not need commands or mode selection. Talk to Design System Creator naturally.

## 1. Build a long-term personal Design System
“我要建立自己的设计系统。我会连续发参考图，先只接收。我说上传完成后先核对，等我说开始分析再分析。”

Design System Creator should verify vision capability, collect without analysis, bind evidence, interview only uncertain preferences, show Design Kernel candidates, then confirm/compile the durable system.

## 2. Make something now
“把这份材料做成一套 PPT / Word / Excel / PDF / 网页。按我现有的设计身份，但这次更冷静、更技术一点。”

If a Kernel exists, use it. If not, create a task-local Temporary Context rather than forcing a full onboarding unless a persistent system is useful and the user wants it.

## 3. Refine an existing artifact
“只重做第 3 页的布局和图表，文字、字体和其他页面不变。”

Design System Creator should preserve stable scope, change the smallest necessary region, re-render/recheck affected output, and not mutate long-term rules unless explicitly requested.

## 4. Compile the daily Runtime Skill
“把已经确认的 Design Kernel 编译成日常 Runtime Skill，并给我 Portable Design System。”

The Runtime Skill carries the confirmed identity/rules; the Portable export defaults to no private source/reference files.

## Two phrases worth remembering for reference collection
- `上传完成` = stop collecting and validate, **not** analyze.
- `开始分析` = authorize analysis after validation.
